# AGENTS.md — Wallpaper Carousel (GNOME Shell)

## Назначение проекта

Это расширение GNOME Shell для быстрого выбора обоев из локальной папки. Оно открывает всплывающую галерею по нажатию на индикатор в верхней панели GNOME и позволяет сменить обои одним кликом.

**Текущая задача:** переработать интерфейс галереи так, чтобы окно было компактным, а все превью имели одинаковые пропорции **16:9**, независимо от размеров исходных изображений.

## Окружение и ограничения

- Целевая среда: **GNOME Shell 51**, EndeavourOS / Arch Linux, Wayland.
- Код расширения: JavaScript под **GJS**, интерфейс — средства GNOME Shell (`St`, `Clutter` и существующие компоненты проекта).
- Установленная локальная копия может находиться в `~/.local/share/gnome-shell/extensions/wallpaper-carousel@d4n1ss1m0/`.
- Перед изменениями изучи реальные файлы репозитория: `extension.js`, `metadata.json`, `stylesheet.css` и остальные существующие файлы. **Не считай, что эти имена/пути гарантированы, пока не проверишь.**
- Сохрани действующую логику выбора и установки обоев, интеграцию с панелью, настройки и существующие пользовательские возможности.
- Не переносить интерфейс на GTK-приложение или отдельное окно: это должен остаться **попап расширения GNOME Shell**.
- Не менять глобальные настройки GNOME и не добавлять сторонние зависимости без необходимости.
- Проверяй совместимость используемых API с GNOME Shell 51: добавление `"51"` в `shell-version` само по себе не гарантирует работу.

## Целевой дизайн

Вместо широкого попапа с тремя колонками — компактная галерея с **двумя колонками и максимум двумя рядами** (4 изображения на страницу).

```text
┌───────────────────────────────────────┐
│ Wallpapers                      [↻]   │
│                                       │
│ ┌────────────────┐ ┌────────────────┐ │
│ │   16:9 фото    │ │   16:9 фото    │ │
│ └────────────────┘ └────────────────┘ │
│ filename.jpg…       wallpaper.png…    │
│                                       │
│ ┌────────────────┐ ┌────────────────┐ │
│ │   16:9 фото    │ │   16:9 фото    │ │
│ └────────────────┘ └────────────────┘ │
│ other-image…        background.jpg…   │
│                                       │
│         [‹]       1 / 3       [›]     │
└───────────────────────────────────────┘
```

### Размеры и размещение

- **Ориентир ширины попапа: 380–400 логических пикселей** (адаптировать к доступному месту на экране).
- Внутренние поля: примерно **16 px**.
- Зазор между карточками: **8–10 px**.
- Целевой размер превью: около **172 × 97 px**, строго **16:9**; реальный размер может подстраиваться под доступную ширину.
- У всех карточек одинаковая ширина, превью одинаковой высоты, аккуратные скругления.
- Не задавать огромную фиксированную высоту: попап должен подстраиваться под число строк (1–2).
- Количество колонок фиксировано: **2**; показывать не более **4 обоев на странице**.
- При большом числе изображений окно не должно расти по вертикали: использовать постраничную навигацию.
- По возможности не допускать выхода попапа за границы экрана на меньших разрешениях и при увеличенном масштабировании.

### Превью изображений

- Все превью визуально **16:9**, независимо от ориентации исходника.
- По умолчанию использовать режим **cover**: пропорциональное масштабирование и центрированная обрезка без растягивания/искажений.
- Для вертикальных изображений допустимо обрезать верх/низ или боковые области ради заполнения формата; **оригинальный файл при этом не изменять**.
- Клик по карточке устанавливает **оригинальное изображение**, а не его обрезанное превью.
- Качественное уменьшение изображений; не декодировать полноразмерные файлы заново при каждом открытии, если существующая архитектура позволяет кеширование/миниатюры.
- Ошибка чтения одного файла не должна ломать всю галерею: показать заглушку и продолжить работу.

### Карточки

- Под превью одна строка имени файла, слишком длинное имя сокращать многоточием.
- Полное имя файла показывать в подсказке при наведении, если это поддерживается применяемыми компонентами.
- Активные обои выделять **тонкой акцентной рамкой** (опционально маленькой галочкой); рамка не должна менять размер карточки и сдвигать сетку.
- Сохранять явное состояние hover/pressed для кликабельных карточек.
- Не добавлять лишние подписи, большие кнопки или декоративные блоки.

### Заголовок и навигация

- Слева заголовок `Wallpapers` (или существующая локализация), справа небольшая кнопка **обновления списка** с подсказкой.
- Убрать отдельную текстовую строку «Обновить список» из нижней части попапа.
- Внизу одна компактная строка: кнопка назад, текущая/общая страница (`1 / N`), кнопка вперёд.
- На первой/последней странице соответствующие стрелки неактивны.
- Если всего одна страница, скрыть пагинацию (либо оставить минимальный индикатор только если это уже предусмотрено архитектурой).
- После обновления списка корректно пересчитать число страниц; не оставаться на несуществующей странице.

## Функциональные требования

1. Расширение по-прежнему открывается из существующего индикатора в верхней панели GNOME.
2. Работает выбор обоев из текущей папки, установленной проектом; существующие настройки пути не теряются.
3. Галерея поддерживает `0`, `1`, `2`, `3`, `4` и более изображений без пустых больших областей.
4. Если обоев нет, показывать компактное пустое состояние с понятным сообщением и возможностью обновить список.
5. Выбранное изображение корректно подсвечивается после смены обоев, переключения страниц и обновления списка.
6. Не должно быть лишнего дублирования обработчиков событий при повторном открытии меню.
7. При отключении расширения корректно освобождать созданные actors, signal handlers, таймеры и другие ресурсы.
8. Сохранить поведение установки обоев, включая обработку светлой/тёмной темы, **если такая логика уже реализована**. Не изобретать новые режимы.

## Требования к реализации

- **Сначала прочитай существующий код**, затем внеси **минимальные адресные изменения**, не переписывая расширение целиком.
- Раздели расчёт страниц, создание карточки, генерацию/показ превью и обновление состояния, если это упрощает поддержку.
- Для размеров карточек используй единый источник значений и учитывай ширину содержимого попапа, отступы и межколоночный зазор.
- Не искажай изображения простым назначением разных ширины и высоты без сохранения пропорций; используй обрезку при рендеринге превью.
- Избегай API, характерных для обычного браузера или GTK4, если они недоступны внутри GNOME Shell.
- Не вводи дополнительную регистрацию `GObject`-типов без необходимости; при её использовании избегай конфликтующих имён классов.
- Не ломай интеграцию с другими расширениями GNOME (например, Blur My Shell) и не меняй чужие элементы панели.
- Не делать `sudo`-операций и не править системные каталоги без явной необходимости.

## Критерии готовности

- [ ] Попап заметно компактнее прежнего, целевая ширина — около 400 px.
- [ ] Галерея — 2 колонки, 4 картинки на страницу.
- [ ] Все превью 16:9, без деформаций, с центрированной обрезкой.
- [ ] На странице с 1–2 картинками **нет пустого второго ряда**.
- [ ] Сохранились смена обоев, выбор папки (если реализован) и индикация активного изображения.
- [ ] Названия в одну строку с многоточием, полное имя доступно через подсказку.
- [ ] Обновление — в заголовке, пагинация — в компактной нижней строке.
- [ ] GNOME Shell 51 загружает и отключает расширение без ошибок.
- [ ] Агент описал, что проверил реально, а что требует проверки пользователем в GUI.

## Важное замечание по проверке

На GNOME Wayland нельзя полагаться на `Alt+F2 → r` как на способ перезапуска Shell. Для обычной проверки можно отключить/включить расширение через `gnome-extensions`; если изменения не применились, может потребоваться выход из сеанса и повторный вход. **Не выполнять выход из сеанса автоматически.**
